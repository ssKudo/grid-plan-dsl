# Conversational Grid Plan DSL

**Agent AI との対話を通じて、建築法規チェック用の建物情報を構造化する軽量表現手法。**

本プロジェクトは、PDF 図面の自動認識（OCR）や BIM/IFC の導入コストに依存せず、実務者の「図面読解力」と Agent AI の「構造化能力」を組み合わせることで、建物モデルを構築するための DSL（ドメイン固有言語）およびワークフローの研究です。

## 📌 コンセプト：抽出から「検証」へ

従来の建築法規自動判定（ACC）の多くは、「BIM や図面から情報を自動抽出する」アプローチを取ります。しかし、PDF OCR の誤認識や図面表記のばらつきは、法規判定のような「1mm の差」が重要な分野では課題となります。

本プロジェクトでは、このアプローチを反転させます。

**「人間が Agent に説明し、AI がモデル化し、PDF OCR はその根拠を照合（検証）するために使う」**

これにより、認識精度の問題を「抽出問題」から「検証問題」へと変換し、小規模な実務者でも低コストに法規チェック準備を行える環境を目指しています。

## 📐 通り芯グリッドモデル

日本の木造住宅で一般的な**「通り芯（X:数字, Y:かな）」**を共通言語として採用し、建物をグラフ構造として定義します。

- **Node (点)**: 通り芯の交点。
- **Edge (線分)**: 交点同士を結ぶ線。ここに「壁」「開口」「建具」「境界」を定義します。
- **Cell (区画)**: 4つのエッジに囲まれた最小単位。ここに「部屋の用途」「設備」を定義します。

### 🛠 データモデルの例

#### 1. 建物外形 (Outline)
原点を決め、辺の方向と長さで定義します。
```yaml
outline:
  unit: mm
  origin: southwest
  path:
    - E 11890
    - N 3000
    - W 5000
    - N 4600
    - W 6890
    - S 7600
    - close
```

#### 2. 部屋定義 (Rooms)
セルの集合として定義します。
```yaml
rooms:
  - id: ldk
    name: LDK
    cells: [い-2, い-3, ろ-2, ろ-3]
```

#### 3. 開口・建具 (Openings)
エッジ（通り芯の間）に紐づけて定義します。
```yaml
openings:
  - id: w1
    type: window
    template: 16520
    edge: "い通り 2-3間"
    room: ldk
```

## 🖼 ASCII アートによる認識確認（フィードバックループ）

Agent AI が内部で保持している認識状態を **ASCII アート**で出力し、ユーザーが即座に視覚的に確認・修正できる仕組みを導入しています。

```text
Legend: WA = 和室, LD = LDK, SE = 洗面, w = 窓, d = ドア

     1    2    3    4    5    6    7
ま   +----+----+----+----+----+----+
    |SE  |SE  |    |LD  |LD  |LD  |
ほ   +----+----+----+----+----+----+
    |SE  |SE  |WA  |LD  |LD  |LD  |
に   +----+----+----+----+----+----+
    |WA  |WA  |WA  |LD  |LD  |LD  |
は   +----+----+----+----+----+----+
    |WA  |WA  |WA  |    |    |    |
ろ   +----+----+----+----+----+----+
    |WA  |WA  |WA  |    |    |    |
い   +--w-+----+----+----+----+----+
```

ユーザーはこれを見て、「和室は は-1 から に-4 までだった」「この窓はLDKではなく和室側だ」と修正指示を出すことで、モデルを精緻化します。

## 🔄 ワークフロー

1. **対話構築**: `外形` $\rightarrow$ `グリッド` $\rightarrow$ `部屋・設備` $\rightarrow$ `建具` の順に Agent へ指示。
2. **視覚確認**: ASCII 平面図による認識確認と修正。
3. **建物カルテ生成**: 法規判定エンジンが処理可能な `building-card.yaml` を出力。
4. **根拠照合**: PDF OCR を使い、「カルテの LDK 面積 18.2m² が、PDF の A-201 図面にあるか」を検証。
5. **法規判定**: 決定的なデータに基づき、OK/NG/不足情報をレポート。
