# Conversational Grid Plan DSL

Conversational Grid Plan DSL は、Agent AI との対話を通じて、住宅法規チェックに必要な建物情報を構造化するための軽量な表現手法およびその構築プロセスの研究プロジェクトです。

## 📌 コンセプト

BIM/IFC の導入コストや、PDF OCR の認識精度の限界に依存せず、**「人間が図面を見ながら AI に説明し、AI がそれを構造化データに変換する」**という対話型アプローチによって、信頼性の高い建物モデルを構築することを目指しています。

### なぜこの手法が必要なのか？
- **OCR の限界**: PDF からの自動抽出は誤認識が多く、法規判定のような「1mm の差」が重要な分野では致命的です。
- **検証への転換**: AI に「抽出」させるのではなく、人間が定義したモデルを AI に「PDF の根拠と照合（検証）」させることで、認識精度の問題を検証問題に変換します。

## 📐 核心的なアイデア：通り芯グリッドモデル

日本の木造住宅で一般的な「通り芯（X:数字, Y:かな）」を共通言語として採用しています。

- **Node (点)**: 通り芯の交点。
- **Edge (線分)**: 交点同士を結ぶ線。壁、開口、建具、境界などを定義します。
- **Cell (区画)**: 4つのエッジに囲まれた最小単位。部屋の用途や設備を定義します。

この構造により、自然言語による指示（例：「い-1からに-4までを和室にする」）を、決定的な座標データ（YAML）へ変換することが可能になります。

## 🛠 ワークフロー

1. **対話による定義**: 外形 $\rightarrow$ グリッド $\rightarrow$ 部屋・設備 $\rightarrow$ 建具 の順で AI に指示。
2. **ASCII 可視化**: AI が内部認識を ASCII アートで出力し、ユーザーが即座に視覚的に確認・修正。
3. **建物カルテ (Building Card) 生成**: 最終的に AI が法規判定エンジンで処理可能な YAML 形式のデータを生成。
4. **根拠照合**: 生成されたデータが実際の PDF 図面と矛盾していないかを AI と共に検証。
